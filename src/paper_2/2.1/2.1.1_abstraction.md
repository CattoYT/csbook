## Data abstraction
**Data abstraction** is a subcategory of abstraction, in which details about how data is stored and represented are hidden, and only the important details are exposed. For example, you may upload an image to Signal when sending a message to someone. Do you know every last detail about how Amazon S3 works when storing that image? No, probably not. But you don't need to know that in order to use Signal, and the details of how the image is stored are abstracted away from you.

Another example in programming is **stacks and queues**. These are abstract data types that hide the details of how they are implemented, and only expose the important operations that can be performed on them. For example, a stack is a data structure that allows you to add and remove items in a last-in-first-out (LIFO) manner, while a queue allows you to add and remove items in a first-in-first-out (FIFO) manner. The details of how these data structures are implemented are hidden from the user, and only the important operations are exposed. This is called **procedural abstraction**.


## Methods of abstraction
Abstraction often involves **grouping together similarities**, to help with problem identification and solution. This is often done by creating **models** of the real world. This is known as **abstraction by generalisation**, allowing a common solution to be found to many problems. For example, an object can be created in a program to represent a real-world object, such as a car. The object can have properties such as make, model, and year, and methods such as start and stop. The start method can be the same for all cars, regardless of make, model, or year. This is an example of a common solution being found to many problems, as the same start method can be used for all cars.

>[!NOTE]
> This is not how, for example, cars, are in the real world, and that's the point. If you're making a game about different types of cars then yes you may need to modify variables such as acceleration etc, but if you're just making some street traffic for a game like Crossy Road you don't care about that, you just need to know that the car can move and has a speed. The details of how the car moves are abstracted away from you.

Another form of abstraction is **abstraction by encapsulation**, where we hide the details of a process and only expose the important parts. This is often done in programming, where we create functions or classes that perform a specific task, and we only need to know how to use them, not how they work internally. This is most common with external libraries - do I know all the intricacies of Tkinter? No, but I know how that doing `newButton = tk.Button(root, text="Click me!")` will create a button. I don't need to know exactly *how* the button is created, just that it is created.


## The need for abstraction
Abstraction is about moving from the real world to the virtual: **removing unnecessary details** and focusing on the important ones.

Abstraction enables more efficient design and implementation of systems. If a problem can be solved in a general way, it can be applied to many different situations, rather than having to solve the same problem over and over again. This is known as **reusability** (i.e. libraries, functions, objects, etc). 

It also allows for **modularity**, where a system can be broken down into smaller, more manageable parts, which can be developed and tested independently. This is often done in programming, where we create functions or classes that perform a specific task, and we can test them independently of the rest of the system. An example of modularity at a much wider scale is the internet. The internet is a modular system, where different parts of the system can be developed and tested independently. For example, the HTTP protocol can be developed and tested independently of the TCP/IP protocol, and vice versa. If you're developing Minecraft server software, you probably don't need to know about HTTP, and modularity helps with this.

Above all, abstraction is about **approachability** and **the chance of solving a problem**; if the only programming language was Assembly, then the number of people who could program would be significantly lower than it is today. Abstraction allows for more people to be able to solve problems, and reduces mental load for people that already understand the problem. 


## Devising models
You will likely be asked to devise models of real-world problems in your exams. To do this, you need to consider four things:
- What is the problem that needs ot be solved?
- What are the important details of the problem based on the audience and purpose?
- How will the model be used?
- Who will use it?
