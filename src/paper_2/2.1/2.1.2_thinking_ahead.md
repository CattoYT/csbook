## Inputs and Outputs
- It is important to consider the different components of a program and how they interact with each other. This includes understanding the inputs and outputs of each component, as well as how they are connected to one another.
- **Inputs** are any data required to solve the problem, and **outputs** are the results produced by the program. By clearly defining the inputs and outputs, we can ensure that each component of the program is working correctly and efficiently.

You need to be able to identify the inputs and outputs in a given system. In the example of a self-service checkout system:
- **Inputs**: Items scanned, payment methods, customer loyalty information, etc.
- **Outputs**: Total cost, receipt, inventory updates, etc.

You would also need to consider how these inputs and outputs are connected to each other, and how these connect to other systems. For example:
- **Cost**: The total cost of the items purchased is calculated based on the inputs of the items scanned and any applicable discounts or promotions. This would then be used to generate a receipt.
- **Integration with point of sale system**: The self-service checkout system would need to be integrated with the point of sale system to ensure that the inventory is updated correctly and that the payment is processed accurately.
- **Theft risks**: The self-service checkout system would need to have measures in place to prevent theft, such as security cameras, weight sensors, and employee monitoring. Weight sensors would be connected to the items scanned for example, as each item has a specific weight, and if the weight of the items in the bagging area does not match the weight of the items scanned, it could indicate that an item was not scanned and is being stolen (this is why self-checkouts can be so annoying to use).

## Preconditions
Preconditions are the conditions that must be met before a program can be executed. These conditions can include things like the availability of certain resources, the state of the system, or the presence of certain data. By clearly defining the preconditions for a program, we can ensure that it will run correctly and efficiently, as a given subroutine can safely expect things to be available for it to use.

For example, a factorial can only be carried out on a non-negative integer. This is specified in the documentation of the function, rather than checked in the function itself. This reduces length and complexity, and saves time and processing power during runtime, as checks are not needed.

If there are no preconditions, the user can be confident that the checks will be in the subroutine itself (e.g. try/catch).

The preconditions for a self-service checkout system might include:
- The system must be powered on and connected to the network.
- The barcode scanner must be functioning correctly.
- The payment processing system must be available and operational.

## Reusable Components
As a whole, clear documentation makes subroutines readable and easier to use. Reusable components (classes, functions, modules, etc) are important in thinking ahead.

During decomposition of a program, multiple problems that have already been solved by other programs can be identified. These problems can be solved by using existing components, usually from external libraries, which can save time and effort in the development process. By reusing existing components, we can also ensure that a program is built on a solid foundation of tested and reliable code.

>[!NOTE]
> You will likely use external libraries in your coursework. For example, `pygame` is commonly used to produce Python games, and `numpy` is commonly used for numerical calculations. These libraries contain many reusable components that can be used to solve common problems, such as drawing graphics or performing mathematical operations.

Benefits and drawbacks of reusable components:
| Benefits | Drawbacks |
| --- | --- |
| Saves time and effort in development | May not be optimised for the specific use case |
| Increases code maintainability | Can introduce dependencies that may cause issues |
| Improves code quality | May have a steeper learning curve for new developers |
| Users may be familiar with the component | May not be compatible with other components or systems |
| The user may be more productive if they are familiar with the component | May not be well-documented or supported |

This works best when used in a suite: for example, LibreOffice Impress can reuse components from LibreOffice Writer and LibreOffice Calc, as they are all part of the same suite. This allows for a consistent user experience and reduces the learning curve for users who are already familiar with one of the components.

## Caching
Caching is the process of storing **instructions and/or data** in a temporary storage area (cache) so that they can be accessed more quickly in the future. Cached data often includes frequently accessed or recently used data so that these may be used again quickly. For example, caching is very common on web pages: this textbook requires CSS and JavaScript to work properly, but these files are shared across every page in the book. Therefore, these files are cached in the browser so that they do not need to be downloaded again for every page. This improves the performance of the website and reduces the load on the server.

> [!WARNING]
> Cache invalidation, where cached data is removed or updated, is considered one of the two hardest problems in computer science, along with naming things. 

A more advanced version of caching is **prefetching**, where instructions are moved from RAM to the CPU cache, before they are needed. Prefetching also occurs in other areas e.g. HTTP with `<link rel="prefetch">`. Prefetching can improve performance, for example by loading CSS before the HTML of a webpage is fully loaded, so that the page can be displayed more quickly.

Where data to be prefetched cannot be known ahead of time, such as loading instructions into the CPU, various algorithms can be used to predict what data will be needed next. However, algorithms are not always accurate; prefetching can also have drawbacks, such as increased memory usage and wasted resources if the wrong data is prefetched. Additionally, large caches can take much longer to search than smaller ones, so cache size limits are often needed based on the available memory, the expected usage patterns of the program, and system processing power.
