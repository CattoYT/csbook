# Programming Techniques

## Selection

Selection is a technique to execute different code depending on a provided condition.  
This comes in the format of either a **switch case** or **if-else chain**

### If-else

If else chains are the standard form of selection, where a condition is evaluated. If the value is true, the corresponding code is executed,  
If the condition is false, the else branch is executed, or the if continues.

## Recursion

Recursion is a programming technique, similar to iteration, where a function calls itself to solve a problem.

To effectively use recursion, a **base case** must be defined to stop the recursion from continuing indefinitely.  
This is the terminating statement, where the function will start unwinding and returning values back up the [call stack](./2.2.1_programming_techniques.md#stack).

A recursive case is used to determine whether to add another layer of recursion, or to return the base case.

Since recursion and iteration are similar techniques, it's often good to be aware of the pros and cons between them.

| Pro                                              | Con                                                                                          |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| Recursion is often easier to read and understand | Recursion can be more memory intensive, since each recursive call is added to the call stack |
| Recursion can be more elegant and simpler        | Recursion can be slower than iteration, since each recursive call has overhead               |
| ?                                                | Recursion has the risk of a stack overflow if the base case is not reached                   |

### Call Stack

> [!NOTE]
> Related chapter: [The stack](../../paper_1/1.4/1.4.2_data_structures.md#stacks)

The call stack is a specialised memory structure at runtime that stores active function calls.

#### The 'building' phase

When a function is called, a new **Stack frame** is added to the top of the stack, containing the function's parameters, local variables, and a pointer containing the address of where to resume execution from.

When the function returns, its frame is removed from the stack, and the program continues executing from the previous frame.

#### Unwinding

After the recursive function has reached its base case, it will begin unwinding and evaluating the result.  
The program will pop stack frames off the stack, returning to the previous function call and continuing execution from where it left off. The return values are used as the parameters for the previous function call, until the original function call at the bottom is reached, and a final result is returned.

| Step | Function call  | Condition (n==1) | Action                                         | Call stack depth          |
| :--- | :------------- | :--------------- | :--------------------------------------------- | :------------------------ |
| 1    | `factorial(4)` | False (`4==1`)   | Calls `factorial(3)`                           | 1 (`factorial(4)` pushed) |
| 2    | `factorial(3)` | False (`3==1`)   | Calls `factorial(2)`                           | 2 (`factorial(3)` pushed) |
| 3    | `factorial(2)` | False (`2==1`)   | Calls `factorial(1)`                           | 3 (`factorial(3)` pushed) |
| 4    | `factorial(1)` | True (`1==1`)    | Begins unwinding. Returns 1                    | 4 (`factorial(4)` pushed) |
| 5    | `factorial(2)` | Unwinding        | Receives 1<br>Calculates `2 * 1`<br>Returns 2  | 3 (`factorial(2)` popped) |
| 6    | `factorial(3)` | Unwinding        | Receives 2<br>Calculates `3 * 2`<br>Returns 6  | 3 (`factorial(2)` popped) |
| 7    | `factorial(4)` | Unwinding        | Receives 6<br>Calculates `4 * 6`<br>Returns 24 | 3 (`factorial(2)` popped) |
